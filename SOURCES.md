# Sources

Design and technique references used while building this tool. None of this code is vendored or copied verbatim unless a specific file says otherwise (e.g. `configs/mabox-skel/`, which is a synced copy of an upstream repo) — this project is a from-scratch Python implementation.

- **[MX-Linux/mx-snapshot](https://github.com/MX-Linux/mx-snapshot)** (forked from [AdrianTM/mx-snapshot](https://github.com/AdrianTM/mx-snapshot), GPLv3) — the reference for the two-mode (`preserving`/`reset`) design, the exclude-list mechanism, and the reset-mode sanitization approach (synthetic `demo` account, `openssl passwd -6` rehash, `/etc/machine-id` handling).
- **`manjaro-tools-iso`** (installed on Mabox via `manjaro-tools-iso-git`) — `/usr/lib/manjaro-tools/util-iso.sh` and `util-iso-boot.sh` are the reference for the xorriso/grub-mkimage hybrid BIOS+UEFI ISO assembly; `/etc/initcpio/hooks/miso` is the reference live-boot mkinitcpio hook. `configs/initcpio/hooks/miso_luks` and `configs/initcpio/install/miso_luks` *are* vendored, modified copies of this hook and its install script (GPLv3, per `manjaro-tools-iso-git`'s license) — used only for `--encrypt` builds; see the module docstring in `mabox_snapshot/luks.py` for what was added and why. `configs/initcpio/hooks/miso_boot` and `configs/initcpio/install/miso_boot` are the same kind of vendored, modified copy of the same stock `miso` hook (GPLv3), used for default non-`--encrypt` builds — added in 0.2.6 to carry a boot-device-resolution fix that couldn't be vendored under the external package's own hook name; see that file's own header comment.
- **`cryptsetup`**'s own `encrypt` mkinitcpio hook (`/usr/lib/initcpio/hooks/encrypt` + `/usr/lib/initcpio/install/encrypt`) — reference for the passphrase-prompt pattern (`plymouth ask-for-password` if running, else a plain retry loop around `cryptsetup open`) reused in `miso_luks`'s new `_mnt_luks_sfs()` function, and for the exact runtime binaries (`cryptsetup`, `libgcc_s.so.1`, `ossl-modules/legacy.so`) a `dm-crypt`-capable initramfs needs. Not usable as-is: its device resolution (`resolve_device()`) can't unlock a file that only exists after another hook mounts the filesystem containing it — see `mabox_snapshot/luks.py`'s module docstring.
- **[Mabox/mabox-skel](https://git.maboxlinux.org/Mabox/mabox-skel)** — Mabox's own official `/etc/skel` template (jgmenu/tint2/openbox/theme defaults for a new user). Synced into `configs/mabox-skel/` as the source for reset-mode's demo-account desktop seeding. Not a byte-for-byte mirror: `configs/mabox-skel/skel/.bashrc` is a local addition (upstream ships no shell rc file at all; see that file's own header comment) and `configs/mabox-skel/skel/.config/libfm/dir-settings.conf` carries a local one-line fix (`ViewMode=thumbnails` → `thumbnail` for `/usr/share/backgrounds`, an upstream typo that crashed pcmanfm on navigation). A future wholesale re-sync from upstream needs to re-apply both by hand unless upstream picks them up first.
- **[Mabox/manjaro-tools-livecd](https://git.maboxlinux.org/Mabox/manjaro-tools-livecd)** — live-session utilities (mhwd, mirrors, dpms). *Not* a Calamares reference — checked directly, it has no installer config at all.
- **The `calamares` package itself** (`/usr/share/calamares/settings.conf` + `modules/*.conf`) — there is no Mabox-specific Calamares repo on git.maboxlinux.org (searched the whole org; only `manjaro-tools-livecd` above turned up, and it's unrelated). Mabox installs its live ISOs with stock upstream Calamares config, so this tool only ever overrides *which branding component* `settings.conf` points at — the install sequence (partition/bootloader/users/...) is always the package's own tested defaults, never hand-written here.
